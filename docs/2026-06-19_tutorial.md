## 1. 项目背景：我们在做什么

本仓库是 [Trinity-RFT](https://github.com/agentscope-ai/Trinity-RFT) 的 fork（`nashjojo/Trinity-RFT`），用途是**放一份 Agentic-RL 入门教程**。

用户在 Trinity-RFT 上做了大量 agentic RL 实验（v11~v33、40 步全程、5seed、eval 等），然后从这些实验中**精心挑选、提炼**出一份 7 章教程。这个 fork 仓库的职责就是**把这份教程交付给读者**。

**核心定位**：教 agentic RL 方法论，不是介绍 Trinity-RFT 软件。Trinity-RFT / Tinker / TuFT / E2B 都是选用的工具，平等呈现、可替换。

## 3. 核心原则与操作红线（必读）

### 3.1 内容筛选：最小必要原则

教程是从大量实验中**挑选出来**的精华。仓库只放"挑选出来的部分"。

**判断标准只有一条**：教程正文（`docs/RL_tutorial/` ch0~ch6 + `docs/2026-06-08_agentic_rl_v22_tutorial.md`）里引用了什么，仓库就放什么。没引用的实验产物一律不提交。

> **不要用文件名模式（如"含 v22"）推断该提交什么**——必须 grep 教程正文确认引用关系。这是之前犯过的错误。

### 3.2 实验产物处理

未被教程引用的实验产物（5seed 结果、eval 热图、稳定性对比图、其他实验报告 v23~v33 等）：
- **不提交到仓库**
- **留在本地磁盘**（作为未跟踪文件，用户后续可能需要）
- **不改 `.gitignore`**（用户后续可能需要追踪它们）

### 3.3 Git 操作红线

| 操作 | 正确做法 | 错误做法（已犯过） |
|---|---|---|
| 移除文件追踪 | `git rm --cached <file>`（保留本地文件） | `git rm <file>`（会删本地文件） |
| `.gitignore` | 不改 | 自作主张加忽略规则 |
| 推送到 fork | `git push git@github.com:nashjojo/Trinity-RFT.git public/copaw_rl`（SSH） | `git push fork ...`（HTTPS 会卡在认证） |
| 文件筛选 | grep 教程正文确认引用 | 用文件名模式猜 |

### 3.4 内容约束

- 实验报告**只保留 `v22_tutorial.md`**，不保留 `v22.md`（40 步全程报告）
- **不提"40 步"**，教程只跑前 19 步
- `_start_v22.sh` 的 `TOTAL_STEPS=19`（与教程一致，不是原始的 40）

### 7.1 新增交互式脚本体系

参考 [tinker-cookbook](https://github.com/thinking-machines-lab/tinker-cookbook) 的交互式教学模式，为 ch2–ch5 每章创建了可运行的配套脚本，放在 `scripts/tutorial/`：

| 文件 | 用途 | 可执行？ |
|---|---|---|
| `ch2_inspect_trajectory.py` | 解析 trajectory 的 ReAct 循环，tool call + result 配对显示 | ✅ `--sample --compare` |
| `ch2_rollout_single.py` | 在线跑一条新 trajectory（需 API key） | ✅（需环境） |
| `ch3_score_trajectory.py` | 回放 reward 4 层计算流程 | ✅ `--sample` |
| `ch4_compute_advantage.py` | GRPO advantage 计算 + 自定义 reward 试验 | ✅ `--sample` / `--rewards` |
| `ch5_inspect_training.py` | LoRA 参数量 + 训练配置 + 时间线 | ✅ `--sample` / `--model` |
| `minimal_rl_loop.py` | 4 步训练循环概念骨架（伪代码，仅供阅读） | — |

样本数据放在 `scripts/tutorial/sample_data/simple_085/`，从 v22 实验真实提取：
- `step1_session.json` — base policy 失败 trajectory (score=0.33, 5 LLM calls)

## 8. 教程结构速览

```
第 0 章：要不要 RL？框架选型？        ← 决策
第 1 章：5 分钟跑通最小训练循环        ← 黑盒 / 操作（19 步，score 72→82）
第 2 章：拆开黑盒 — 单次 rollout 内部
第 3 章：拆开黑盒 — reward 怎么算
第 4 章：拆开黑盒 — GRPO advantage 怎么来
第 5 章：拆开黑盒 — 模型权重怎么更新
第 6 章：改黑盒 — 换任务、换模型、换 reward  ← 实验
```

技术栈：Trinity-RFT（框架）+ Tinker/TuFT（训练后端）+ E2B（sandbox）+ multi-step GRPO（G=8）+ Qwen3-4B（LoRA rank=8）+ queries_simple v20_top8（8 个真实编程任务）。
